На основании [описания](./overview.md) на первое время план действий такой:

- [*] В имеющемся проекте завести модуль для контроллера (котлиновский проект, вероятно в виде гредл-модуля, допускать возможность шарить общий код между UI частью (composeApp) и кодом контроллера, запуск просто в виде jar-ника)
- [ ] Сделать папку для общих протобуфин
- [ ] Cпроектировать основные протки для канала данных (запрос, ответ)
- [ ] Спроектировать основные протки для канала управления (создание прокси с заданными параметрами, запуск, остановка, статус прокси, общий статус контроллера)
- [ ] Спроектировать gRPC API для связки "контроллер - mitmproxy"
    - [ ] Отправка перехваченного запроса в контроллер - пока без возвращаемого значения
    - [ ] Отправка перехваченного ответа в контроллер - без возвращаемого значения
    - [ ] Оповещение контроллера о запуске прокси
- [ ] Спроектировать Python-аддон для mitmproxy
    - [ ] Базовый скрипт с приемом запроса и ответа
    - [ ] Работа с gRPC ручками в асинхронном формате
- [ ] Контроллер - начало
    - [ ] Реализация gRPC API для приема проток с mitmproxy-аддона
    - [ ] Функционал старта прокси с аддоном
    - [ ] Функционал остановки ранее запущенной прокси с аддоном
