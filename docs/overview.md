## Проект Proxiya

### Общее описание

Proxiya - это современный и удобный UI-клиент для прокси-сниффера mitmproxy. Позволяет запускать процессы mitmproxy и с их помощью работать с траффиком устройств и приложений. Аналог Proxyman, Charles, Fiddler.

### Статус

Проект находится в стадии разработки (по вечерам в свободное время)

### Планируемый функционал

- Создание, конфигурирование, запуск экземпляров mitmproxy
- Просмотр содержимого запросов и ответов, перехватываемых этими проксями
- Фильтрация запросов
- Модификация перехватываемых запросов и ответов (map local, map remote)
- Повтор запроса (replay, edit&replay)
- Экспорт запросов и ответов в разные форматы
- Сохраняемые пресеты для фильтров, модификаторов
- Пользовательские ячейки (user cells) - способ извлекать полезные куски из сырых данных запроса/ответа и визуально их выделять/размещать
- Цепи обработки (processing chains) - визуальный редактор для кастомной настройки способов и логики обработки запросов и/или ответов
- Скриптинг
- Полезные утилиты - автонастройка сертификатов на системе/эмуляторе/девайсе
- Просмотр gRPC запросов, Protobuf
... _(список дополняется)_

### Архитектура

Части системы:

- **Desktop-приложение на Compose Multiplatform** - десктопное приложение на Compose Multiplatform, построенное на базе архитектуры Decompose
- **Контроллер проксей** - JVM-приложение на Kotlin для управления инстансами прокси, является уровнем абстракции над mitmproxy (и потенциально над любым другим консольным/API прокси-сниффером)
- **Python-аддон для mitmproxy** - запускается для инстанса mitmproxy и пересылает перехваченный трафик в контроллер

#### Коммуникация

Взаимодействие между частями строится на базе протокола gRPC:
- **UI ↔ Контроллер** - gRPC API для управления прокси
- **Контроллер ↔ mitmproxy** - gRPC API для получения трафика
- **Единые протоколы** - общие protobuf-сообщения для HTTP-запросов/ответов, сущностей и параметров проксей

##### Каналы связи:

**Канал данных (Data Channel):**
- `mitmproxy → ProxyInstanceDataService → Controller` - передача перехваченного трафика
- `Controller → ProxyDataService → UI` - стриминг трафика в интерфейс
- Bidirectional streaming для интерактивной обработки запросов/ответов

**Канал управления (Control Channel):**
- `UI → ProxyControlService → Controller` - управление жизненным циклом прокси
- `mitmproxy → ProxyInstanceControlService → Controller` - уведомления о статусе прокси
- `Controller → ProxyControlService → UI` - обновления статуса в реальном времени

##### gRPC сервисы:
- **ProxyControlService** - управление прокси для UI (создание, запуск, остановка etc.)
- **ProxyDataService** - стриминг данных для UI (перехваченный трафик)
- **ProxyInstanceControlService** - уведомления от прокси-инстансов (статус, ошибки)
- **ProxyInstanceDataService** - передача трафика от прокси-инстансов

### Технологии

- **UI (composeApp)**
    - Kotlin + Compose Multiplatform
    - Decompose (архитектура компонентов, навигация)
    - Koin (dependency injection)
    - gRPC + Protobuf (jvmMain)
    - Kotlin coroutines/flow
    - Material Design 3
- **Контроллер**
    - Kotlin + JVM
    - gRPC + Protobuf
    - Kotlin coroutines/flow
    - Управление процессами mitmproxy
- **Аддон (mitmproxy)**
    - Python3 + asyncio
    - gRPC + Protobuf
    - Интеграция с mitmproxy API
